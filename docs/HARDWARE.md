# ESP32 setup

## Hardware and libraries

Use an ESP32 board, DHT22, SSD1306 128 × 64 I2C OLED, three LEDs with suitable resistors, a push button, and a buzzer. Wiring is defined in the sketch:

| Part | Pin |
| --- | --- |
| DHT22 data | 4 |
| OLED SDA / SCL | 21 / 22 |
| Button | 15; INPUT_PULLUP |
| Green / red / blue LED | 18 / 19 / 2 |
| Buzzer | 23 |

Install the ESP32 Arduino board package plus ArduinoJson, Adafruit GFX, Adafruit SSD1306, and DHT sensor libraries with their dependencies. Library/board combinations have not been compilation-tested in this release.

## Configure and flash

1. Copy config.example.h to config.h within firmware.
2. Enter local Wi-Fi credentials and the backend computer's LAN IP.
3. Start FastAPI on port 8000 with --host 0.0.0.0 for LAN testing.
4. Open the sketch in Arduino IDE, select your ESP32 board/serial port, and upload.
5. Inspect Serial Monitor at 115200 baud.

config.h is ignored by Git. Never publish credentials in the sketch or example file. Some Arduino IDE versions expect the sketch directory to match the .ino basename; use the IDE's save/move workflow if prompted and keep config.h beside the sketch.

Telemetry posts every five seconds to /api/sensor-data. Short button presses change OLED pages; a long press queues an anomaly. Temperature/humidity come from the DHT22 or fallback values. Electrical readings are generated by the solar model, not a power sensor.

## USB forwarding

From the repository root:

~~~powershell
.\.venv\Scripts\python.exe esp32_serial_bridge.py --port COM7 --baud 115200
~~~

Replace COM7 or omit --port to attempt discovery. Close Serial Monitor before opening the port. The bridge extracts JSON from serial lines and posts it to the API. Its --url option expects the complete ingestion endpoint.

Do not forward USB readings while the same board already delivers them over Wi-Fi. Ingestion does not deduplicate duplicate packets.

## Earlier access-point bridge

esp32_bridge.py expects compatible firmware serving http://192.168.4.1/api/data. The bundled client-mode sketch does not implement that endpoint. This bridge is retained for earlier hardware experiments.

## Validation boundary

No physical board, wiring, sensor calibration, library compilation, or electrical measurement integration was tested for this release. Backend accounting currently assumes 1.5 seconds per accepted reading, unlike the five-second firmware interval. Correct timestamp integration before using measured hardware totals.
